# GHOSTFIRE

Браузерный воксельный FPS: дуэль 1v1 против призрака — записи реального игрока,
которая двигается по реплею, но **целится живьём**. Three.js через importmap с CDN,
без сборщиков. Работает с любого статик-хостинга.

## Запуск

```
npx http-server -p 8123 -c-1 .
# открыть http://localhost:8123
```

Регенерация контента:

```
node tools/gen_maps.mjs     # maps/*.json
node tools/gen_ghosts.mjs   # ghosts/*.json (встроенные боты)
```

## Архитектура записи призрака (js/replay.js)

Поведение игрока пишется снапшотами **20/сек**. Формат бинарный (little-endian),
затем base64 — компактный и готовый ехать по WebSocket в V2 как есть:

```
[0..3]   magic "GF01"
[4..5]   uint16 tickRate (20)
[6..9]   uint32 frameCount
[10..13] uint32 shotCount
[14..17] uint32 pickupCount
frameCount × 21 байт: float32 x,y,z,yaw,pitch; uint8 flags
         flags: bit0 прыжок; bits1-2 id оружия
shotCount × 6 байт:  uint32 tick; uint8 weapon; uint8 hit (0 мимо/1 тело/2 голова)
pickupCount × 5 байт: uint32 tick; uint8 weapon
```

Обёртка для шеринга/хранения: `{ v, map, name, score, data: base64 }`,
для ссылки сжимается LZ-string → `?ghost=<код>`.

**Ключевая механика:** призрак движется точно по записи (позиции интерполируются,
запись зациклена), но в записанные моменты выстрелов стреляет в **текущую** позицию
живого игрока: реакция 150–300 мс, вероятность попадания = меткость оригинала из
записи (clamp 0.15–0.92) ± разброс, промахи уводятся на 3–10°. Стены честно
блокируют выстрел (DDA-рейкаст). Поэтому дуэль ощущается как PvP, а не как тир.

После каждого матча запись **лучшего раунда** (быстрейшая победа) сохраняется как
призрак игрока (`Platform.savePlayer`).

## Формат карты (maps/*.json)

```json
{
  "id": "arena01", "name": "…",
  "palette": { "1": "#hex", … },          // тип блока → цвет
  "blocks": [[x, y, z, type], …],          // воксели, сетка 1 м
  "spawns": [[x, y, z, yawDeg], …],        // 2 точки
  "weapons": [{ "type": 1, "pos": [x,y,z] }] // 1 дробовик, 2 рейлган
}
```

Весь рендер строится из JSON: один merged-меш (vertex colors, скрытые блоки
отброшены), коллизии — Set вокселей. Будущий редактор пишет такой же JSON.

## Параметры движения / урона

| Параметр | Значение |
|---|---|
| Скорость | 8 м/с, мгновенно (без инерции, полный контроль в воздухе, распрыжка ок) |
| Прыжок / гравитация | 8.5 м/с / 24 м/с² |
| AABB игрока | 0.7×1.7 м, глаза 1.6 |
| HP | 100, без регенерации |
| Пистолет | 12 урона, кд 0.28с, бесконечный |
| Дробовик | 8 дробин × 7, разброс 0.085, спад урона с дистанцией |
| Рейлган | 100 урона, зарядка 0.8с, hitscan насквозь |
| Голова | ×2 (головы кубов большие — 0.55 м) |
| Респаун пушек | 10 с |
| Матч | до 5 побед в раундах |

## Производительность

Merged geometry карты (1 draw call), пулы трассеров (24) и кубиков смерти (40),
pixelRatio cap 2, BasicShadowMap (жёсткие тени), туман скрывает дальний план.

## Известные проблемы

- Pointer lock недоступен в sandbox-iframe (встроенные превью) — работает фолбэк:
  камера от движения мыши без захвата; в обычной вкладке всё штатно.
- Призрак не сталкивается с геометрией (движется по записи) — записи, сделанные
  на другой карте, могут проходить сквозь стены. Шеринг несёт id карты, поэтому
  штатный путь безопасен.
- В фоновой вкладке rAF троттлится — отсчёт/матч замирают (не баг для игрока).
- Автоогонь на мобиле проверяет LOS от призрака, конус 6° — может огорчать на
  сверхдальних дистанциях (намеренно, чтобы не палил через пол-карты).

## План V2

### Сеть
- Colyseus-сервер: тот же протокол снапшотов 20/сек по WebSocket (replay.js уже
  environment-agnostic), серверная валидация попаданий, матчмейкинг по рейтингу
  призраков ("сначала побей призрака — потом живого хозяина").

### UGC и монетизация (ядро стратегии)
Экономика создателей — как в Roblox, но в нише аренного FPS.
**Редакторы карт и скинов уже реализованы** (editor.html): карта сохраняется
в игру и шарится кодом; призрак с пользовательской карты уезжает в шеринге
вместе с картой (`entry.mapData`); скин применяется к игроку/призраку/пушкам.
Дальше:
- Продажа скинов за твёрдую валюту, доля автору, витрина "скин недели".
- Публикация карт: плейлисты популярных, промо-слоты за донат.

### Экономика: госткоины (каркас реализован)
Двухступенчатая схема: **Яны → госткоины (только в одну сторону) → всё остальное**.
- Паки коинов (skins/shop.json → packs) — единственные товары в каталоге Яндекса;
  заглушка `Platform.buyCoinsPack` уже стоит, при интеграции меняется на
  `ysdk.getPayments().purchase()`.
- Магазин скинов в игре (экран «Магазин»): встроенные скины за коины,
  кошелёк/владение — `Platform.loadWallet/saveWallet` (стартовый бонус 100).
- UGC-скины (V2): автор публикует скин → покупки за коины → автору процент
  в коинах (Яндекс не выплачивает деньги игрокам, поэтому вся экономика
  создателей обязана жить во внутренней валюте). Нужен бэкенд-каталог.

### Яндекс Игры (проверено по SDK)
- Вся интеграция — только в js/platform.js: `YaGames.init()` → initSDK,
  `ysdk.adv.showRewardedVideo/showFullscreenAdv` → наши хуки,
  `player.setData/getData` → savePlayer/loadPlayer (облако), лидерборды → submitScore.
- **Встроенная валюта (Яны)**: Payments API (`ysdk.getPayments()`), каталог
  покупок в консоли разработчика — туда идут скины/слоты призраков.
- Нюанс: Яндекс не выплачивает деньги игрокам-авторам UGC → доля автору
  реализуется внутренней мягкой валютой, реальные деньги — разработчику.
- Требования: работа в iframe (фолбэк без pointer lock уже есть), билд zip-ом,
  модерация, обязательный вызов LoadingAPI.ready().
- **Рынок призраков**: платные "тренеры" — призраки топ-игроков; сезонные
  башни призраков (ladder) с наградами-косметикой.
- **Rewarded-хуки** (заглушки уже стоят): реванш с того же счёта, второй слот
  своего призрака, ускорение респауна пушки на раунд.
- **Battle pass**: сезонные задания ("выиграй 3 дуэли дробовиком"), награды —
  только косметика, баланс не продаём.
- Interstitial между матчами (хук стоит на экране поражения).
