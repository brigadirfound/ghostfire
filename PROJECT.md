# GHOSTFIRE

Браузерный воксельный FPS: дуэль 1v1 против призрака — записи реального игрока,
которая двигается по реплею, но **целится живьём**. Three.js через importmap,
self-host (без CDN, без сборщиков). Работает с любого статик-хостинга.

Прод: https://brigadirfound.github.io/ghostfire/ · Репо: github.com/brigadirfound/ghostfire

## Запуск

```
npx http-server -p 8123 -c-1 .
# открыть http://localhost:8123
```

Регенерация контента (запускать в этом порядке, если менялись карты):

```
node tools/gen_maps.mjs       # maps/*.json
node tools/gen_ghosts.mjs     # ghosts/*.json — матрица 5 карт × 5 сложностей
node tools/check_maps.mjs     # валидация: спавны/пропасти/стены
node tools/check_pickups.mjs  # валидация: точки оружия не внутри стен
```

Сборка билда для Яндекс Игр: `powershell -File tools/pack_yandex.ps1` → `ghostfire_yandex.zip`.

Генерация арт-ассетов (скайбокс/фон меню) через Nano Banana:
`node tools/gen_skybox.mjs [--force]` — ключ `VISIONARY_API_KEY` читается в
рантайме из `.env` (свой либо `D:/games/chislopad/.env` либо `berry-merge/.env`),
в репозиторий не попадает.

## Архитектура записи призрака (js/replay.js)

Поведение игрока пишется снапшотами **20/сек**. Формат бинарный (little-endian),
затем base64 — компактный и готовый ехать по WebSocket в V2 как есть:

```
[0..3]   magic "GF01"
[4..5]   uint16 tickRate (20)
[6..9]   uint32 frameCount
[10..13] uint32 shotCount
[14..17] uint32 pickupCount
frameCount × 21 байт: float32 x,y,z,yaw,pitch; uint8 flags
         flags: bit0 прыжок; bits1-3 id оружия (0..5, было 2 бита/0..2,
         расширено без слома старых записей — бит3 в них всегда 0)
shotCount × 6 байт:  uint32 tick; uint8 weapon; uint8 hit (0 мимо/1 тело/2 голова)
pickupCount × 5 байт: uint32 tick; uint8 weapon
```

Обёртка для шеринга/хранения: `{ v, map, name, score, data: base64 }`
(+ `mapData`, если призрак с пользовательской карты — уезжает вместе с картой).
Для ссылки сжимается LZ-string → `?ghost=<код>` или `?payload=<код>` на Яндексе.

**Ключевая механика:** призрак движется точно по записи (позиции интерполируются,
запись зациклена), но в записанные моменты выстрелов стреляет в **текущую** позицию
живого игрока: реакция 150–300 мс, вероятность попадания = меткость оригинала из
записи (clamp 0.15–0.92) ± разброс, промахи уводятся на 3–10°. Стены честно
блокируют выстрел (DDA-рейкаст). Поэтому дуэль ощущается как PvP, а не как тир.

После каждого матча запись **лучшего раунда** (быстрейшая победа) сохраняется как
призрак игрока (`Platform.savePlayer`).

## Формат карты (maps/*.json)

```json
{
  "id": "arena01", "name": "…",
  "palette": { "1": { "color": "#hex", "tex": "grass_dirt" }, … },
  "blocks": [[x, y, z, type], …],            // воксели, сетка 1 м
  "spawns": [[x, y, z, yawDeg], …],           // 2 точки
  "weapons": [{ "type": 1, "pos": [x,y,z] }]  // 1..5, см. WEAPONS в weapons.js
}
```

`palette[type]` — либо `{color, tex}` (тонировка процедурного тайла из
`js/textures.js`: stone/brick/planks/grass_dirt/sand/metal/crate/concrete/neon/glass),
либо просто `"#hex"` (легаси-формат старых UGC-карт — рендерится чистым цветом,
без текстуры). Весь рендер строится из JSON: один merged-меш с общим атласом
(vertex colors × UV на тайл, один draw call), коллизии — Set вокселей.
Kill-zone: `y < -1.5` = мгновенная смерть (для карт с пропастью — Блоки, Мосты).

Редактор (`editor.html`) пишет тот же JSON.

## Оружие: 6 моделей (js/weapons.js)

Модели — Quaternius "Modular Sci-Fi Guns" (CC0, без атрибуции),
`assets/weapons/{key}.gltf`. Материалы одинаковые во всех моделях
(`Black/Grey/White/Main`) — перекраска по скину без доп. ассетов:
`Main`→accent, `Black`→grip, `Grey`/`White`→body. Поэтому «несколько скинов» —
это просто новые наборы цветов в `skins/shop.json`, без новых 3D-файлов.

**Нормализация при загрузке** (`normalizeModel` в weapons.js) — важно при
правке: исходники пака смотрят стволом вдоль **+X** и имеют разный
неоткалиброванный масштаб. При первой загрузке модель один раз поворачивается
(+X→-Z, вперёд от игрока), центрируется по bbox и масштабируется под
`TARGET_LENGTH[key]` в игровых метрах. Если пушка выглядит боком или
гигантской/крошечной — правится тут, а не в `player.js`.

ID стабильны (0-2 — исходные, протокол записи их не меняет):

| id | key | урон | кулдаун | дальность | особенность |
|---|---|---|---|---|---|
| 0 | pistol | 12 | 0.28с | 80 | старт, бесконечный |
| 1 | shotgun | 7×8 дробин | 0.85с | 32 | спад урона, в упор |
| 2 | railgun | 100 | заряд 0.8с | 120 | заряд перед выстрелом |
| 3 | smg | 9 | 0.09с | 55 | близко, спрей |
| 4 | ar | 18 | 0.18с | 90 | универсал |
| 5 | sniper | 80 | 1.6с | 150 | дальний, в связке с хедшотом ×2 почти всегда килл |

Респаун пикапов — 10с. Пикапы smg/ar/sniper на arena01/02/04/05
(arena03 намеренно rail-only aim-карта). Редактор карт — 5 инструментов
точек оружия, редактор скинов — 6 панелей цветов.

**Кисть от первого лица** (`player.js` `_buildHand`): маленький воксельный
кулак+манжета у грипа, цвета из `skin.body.arms/torso` + яркая полоска
цветом `skin.tracer` (чтобы не терялась на тёмных скинах). Не привязана к
геометрии пушки — размер фиксирован, не растёт вместе со снайперкой/рейлганом.
Покачивается синхронно с view-моделью пушки при ходьбе.

## Скайбокс (js/game.js)

Большой цилиндр (радиус 140, высота 500, `BackSide`) вокруг игрока с
текстурой `assets/skybox.jpg` на внутренней стороне; позиция следует за
камерой по X/Z каждый кадр в главном цикле. **Не** используй
`scene.background = texture` напрямую и **не** используй
`EquirectangularReflectionMapping` — оба варианта проверены и сломаны:
первый даёт статичный, не поворачивающийся с камерой фон («карта выглядит
приклеенной поверх скриншота»), второй — искажение «tiny planet» (текстура
не является честной сферической 360°-панорамой, только широкий кадр города,
поэтому сферическая/equirect-развёртка схлопывает её в точку на полюсах).
У цилиндра нет полюсов — искажений нет, обзор поворачивается вместе с камерой
естественно. Один шов сзади (края текстуры сходятся) — в аренной дуэли почти
не заметен. Высота с большим запасом, чтобы открытый верх цилиндра не попадал
в кадр даже на высоких точках карт (башни arena05).

## Производительность

Merged geometry карты (1 draw call на карту), процедурный атлас текстур
(1 draw call на набор блоков), пулы трассеров (24) и кубиков смерти (40),
pixelRatio cap 2, BasicShadowMap (жёсткие тени), туман скрывает дальний план,
GLTF-модели оружия кешируются (грузятся один раз, дальше только clone()).

## Экономика: госткоины

Двухступенчатая схема: **Яны → госткоины (только в одну сторону) → всё остальное**.
- Паки коинов (`skins/shop.json` → `packs`) — единственные товары в каталоге
  Яндекса; `Platform.buyCoinsPack` на Яндексе зовёт `ysdk.getPayments().purchase()`,
  локально — заглушка. Кнопки скрыты за `CONFIG.paymentsEnabled` (сейчас false).
- Награда за матч (`js/economy.js`): 8 базовых + 25×множитель сложности
  (1/1.5/2/2.5/3) + бонусы (сухая 5:0 +15, призрак друга +40), первая победа
  дня ×2, rewarded-кнопка «Удвоить» на экране результатов. Анти-абьюз:
  бонус за одного и того же призрака друга не чаще 3 раз в день (хеш записи).
- Магазин скинов: 5 встроенных за коины + слот «Свой скин» (редактор) за 300;
  кошелёк/владение — `Platform.loadWallet/saveWallet` (стартовый бонус 100).

## Яндекс Игры

`js/platform.js` автоопределяет окружение: пробует загрузить `/sdk.js`
(существует только на CDN Яндекса) → настоящий SDK; иначе localStorage-заглушки.
Локальная разработка и GitHub Pages работают без изменений. Реализовано:
`YaGames.init`, rewarded/interstitial реклама (глушит звук на время показа),
облачные сейвы (`player.setData/getData` + localStorage-фолбэк), лидерборды,
покупки Payments с consume, `LoadingAPI.ready()` в конце boot (после прелоадера).

**Перед заливкой в консоль**:
1. Вписать ID игры в `CONFIG.yandexAppId` (js/config.js) — без него шеринг
   внутри Яндекса работает кодом, а не ссылкой на каталог
2. Завести 3 товара `pack_s`/`pack_m`/`pack_l` (цены в Янах — см. `skins/shop.json`)
   и лидерборд `wins`, затем `paymentsEnabled: true`
3. `powershell -File tools/pack_yandex.ps1` → загрузить zip в черновик игры

**Шеринг по окружениям**: на Яндексе —
`https://yandex.ru/games/app/<yandexAppId>?payload=<код>` (только внутри
Яндекса, внешних доменов в UI нет — прошёл аудит модерации); вне Яндекса —
`<CONFIG.shareBaseUrl>?ghost=<код>`.

## Известные проблемы

- Pointer lock недоступен в sandbox-iframe (встроенные превью) — работает
  фолбэк: камера от движения мыши без захвата; в обычной вкладке всё штатно.
- Призрак не сталкивается с геометрией (движется по записи) — записи с другой
  карты могли бы проходить сквозь стены, но шеринг несёт `mapData`, поэтому
  штатный путь безопасен.
- В фоновой вкладке rAF троттлится — отсчёт/матч замирают (не баг для игрока).
- Автоогонь на мобиле проверяет LOS от призрака, конус 6° — может огорчать на
  сверхдальних дистанциях (намеренно, чтобы не палил через пол-карты).
- Скайбокс-цилиндр: один шов сзади там, где сходятся края текстуры (см. раздел
  «Скайбокс» выше) — компромисс, не баг.

## План V2

### Сеть
- Colyseus-сервер: тот же протокол снапшотов 20/сек по WebSocket (replay.js уже
  environment-agnostic), серверная валидация попаданий, матчмейкинг по рейтингу
  призраков («сначала побей призрака — потом живого хозяина»).

### UGC и монетизация (ядро стратегии)
Экономика создателей — как в Roblox, но в нише аренного FPS. Редакторы карт и
скинов уже реализованы (см. выше). Дальше:
- Продажа скинов за госткоины, доля автору **в коинах** (Яндекс не платит
  деньгами игрокам — см. раздел «Экономика»), витрина «скин недели».
- Публикация карт: общий каталог/плейлисты популярных, промо-слоты за донат.
  Нужен простенький бэкенд (сейчас карты и скины только локальные/шеринг-кодом).
- **Рынок призраков**: платные «тренеры» — призраки топ-игроков; сезонные
  башни призраков (ladder) с наградами-косметикой.
- **Battle pass**: сезонные задания («выиграй 3 дуэли дробовиком»), награды —
  только косметика, баланс не продаём.

### Прочее
- Зоны урона по конечностям, килфид, статистика попаданий по зонам.
- Спектатор-реплей целого матча (формат уже пишет всё нужное).

- 3D-превью скина в карточке магазина; маски отдельным дешёвым слотом.
