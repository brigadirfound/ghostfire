# GHOSTFIRE

Браузерный воксельный FPS: дуэль 1v1 против призрака — записи реального игрока,
которая двигается по реплею, но **целится живьём**. Three.js через importmap,
self-host (без CDN, без сборщиков). Работает с любого статик-хостинга.

Прод: https://brigadirfound.github.io/ghostfire/ · Репо: github.com/brigadirfound/ghostfire

## Запуск

```
npx http-server -p 8123 -c-1 .
# открыть http://localhost:8123
```

Регенерация контента (запускать в этом порядке, если менялись карты):

```
node tools/gen_maps.mjs       # maps/*.json
node tools/gen_ghosts.mjs --seed=ghostfire-v1 # детерминированная матрица 5×5
npm test                      # все проверки одним раннером, без npm-зависимостей
```

`gen_maps.mjs` сохраняет уже назначенное поле `skybox`, если генератор карты
запущен повторно. `gen_ghosts.mjs` не использует ambient `Math.random`: один и
тот же seed даёт те же записи.

Сборка для Яндекс Игр: `powershell -File tools/pack_yandex.ps1` →
`ghostfire_yandex.zip`. Сборщик по умолчанию отказывается работать с dirty
worktree; осознанный override — `-AllowDirty`. ZIP получает фиксированное время
из commit, сортированный список файлов, внутренний `release-manifest.json` и
sidecar-файлы с SHA-256/manifest. Публикуемый набор берётся из
`tools/lib/runtime.mjs`; GitHub Pages использует ровно тот же whitelist.

Небо: `node tools/fetch_sky.mjs` (см. раздел «Купол неба»).
Генерация арт-ассетов через Visionary API осталась для иконок и карточек
магазина: `node tools/gen_icons.mjs`, `node tools/gen_skin_cards.mjs`. Ключ
`VISIONARY_API_KEY` читается только из environment или локального `.env` этого
репозитория; инструменты записывают SHA-256 и provenance-метаинформацию.

## Архитектура записи призрака (js/replay.js)

Поведение игрока пишется снапшотами **20/сек**. Формат бинарный (little-endian),
затем base64 — компактный и готовый ехать по WebSocket в V2 как есть:

```
[0..3]   magic "GF01"
[4..5]   uint16 tickRate (20)
[6..9]   uint32 frameCount
[10..13] uint32 shotCount
[14..17] uint32 pickupCount
frameCount × 21 байт: float32 x,y,z,yaw,pitch; uint8 flags
         flags: bit0 прыжок; bits1-3 id оружия (0..5, было 2 бита/0..2,
         расширено без слома старых записей — бит3 в них всегда 0)
shotCount × 6 байт:  uint32 tick; uint8 weapon; uint8 hit (0 мимо/1 тело/2 голова)
pickupCount × 5 байт: uint32 tick; uint8 weapon
```

Обёртка для шеринга/хранения: `{ v, map, name, score, data: base64 }`
(+ `mapData`, если призрак с пользовательской карты — уезжает вместе с картой).
Для ссылки сжимается LZ-string → `?ghost=<код>` или `?payload=<код>` на Яндексе.

**Ключевая механика:** призрак движется точно по записи (позиции интерполируются,
запись зациклена), но в записанные моменты выстрелов стреляет в **текущую** позицию
живого игрока: реакция 150–300 мс, вероятность попадания = меткость оригинала из
записи (clamp 0.15–0.92) ± разброс, промахи уводятся на 3–10°. Стены честно
блокируют выстрел (DDA-рейкаст). Поэтому дуэль ощущается как PvP, а не как тир.

После каждого матча запись **лучшего раунда** (быстрейшая победа) сохраняется как
призрак игрока (`Platform.savePlayer`).

## Формат карты (maps/*.json)

```json
{
  "id": "arena01", "name": "…",
  "skybox": "assets/sky/arena01.jpg",
  "palette": { "1": { "color": "#hex", "tex": "grass_dirt" }, … },
  "blocks": [[x, y, z, type], …],            // воксели, сетка 1 м
  "spawns": [[x, y, z, yawDeg], …],           // 2 точки
  "weapons": [{ "type": 1, "pos": [x,y,z] }]  // 1..5, см. WEAPONS в weapons.js
}
```

`palette[type]` — либо `{color, tex}` (тонировка процедурного тайла из
`js/textures.js`: stone/brick/planks/grass_dirt/sand/metal/crate/concrete/neon/glass),
либо просто `"#hex"` (легаси-формат старых UGC-карт — рендерится чистым цветом,
без текстуры). Весь рендер строится из JSON: один merged-меш с общим атласом
(vertex colors × UV на тайл, один draw call), коллизии — Set вокселей.
Kill-zone: `y < -1.5` = мгновенная смерть (для карт с пропастью — Блоки, Мосты).

Редактор (`editor.html`) пишет тот же JSON, сохраняет безопасное назначение
skybox при загрузке карты и ограничивает импорт по длине, числу блоков/пикапов,
координатам и схеме до передачи платформенному валидатору.

Обе вкладки редактора ждут `Platform.initSDK()`, выбирают RU/EN из
`Platform.detectedLang` (ручное переключение сохраняется локально) и используют
те же cloud/local слоты, что игра. Успех показывается только если `save*`
вернул `true`. При `pagehide` останавливаются оба rAF, снимаются listeners,
освобождаются OrbitControls, WebGL-контексты, геометрии, материалы и текстуры.
Импорт изображений ограничен 5 МБ/4096 px и безопасными типами; пиксель-арт
нормализуется до 16×16 (рендер поддерживает только ограниченные размеры).

## Оружие: 6 моделей (js/weapons.js)

Модели — Quaternius "Modular Sci-Fi Guns" (CC0, без атрибуции),
`assets/weapons/{key}.gltf`. Материалы одинаковые во всех моделях
(`Black/Grey/White/Main`) — перекраска по скину без доп. ассетов:
`Main`→accent, `Black`→grip, `Grey`/`White`→body. Поэтому «несколько скинов» —
это просто новые наборы цветов в `skins/shop.json`, без новых 3D-файлов.

**Нормализация при загрузке** (`normalizeModel` в weapons.js) — важно при
правке: исходники пака смотрят стволом вдоль **+X** и имеют разный
неоткалиброванный масштаб. При первой загрузке модель один раз поворачивается
(+X→-Z, вперёд от игрока), центрируется по bbox и масштабируется под
`TARGET_LENGTH[key]` в игровых метрах. Если пушка выглядит боком или
гигантской/крошечной — правится тут, а не в `player.js`.

ID стабильны (0-2 — исходные, протокол записи их не меняет):

| id | key | урон | кулдаун | дальность | особенность |
|---|---|---|---|---|---|
| 0 | pistol | 12 | 0.28с | 80 | старт; магазин 12, перезарядка 1.1с |
| 1 | shotgun | 7×8 дробин | 0.85с | 32 | спад урона, в упор; магазин 6, 1.7с |
| 2 | railgun | 100 | заряд 0.8с | 120 | заряд перед выстрелом; магазин 3, 2.0с |
| 3 | smg | 9 | 0.09с | 55 | близко, спрей; магазин 30, 1.4с |
| 4 | ar | 18 | 0.18с | 90 | универсал; магазин 25, 1.5с |
| 5 | sniper | 80 | 1.6с | 150 | дальний, хедшот ×2 почти всегда килл; магазин 5, 1.9с |

**Поза вьюмодели** (`VIEW_POSE` в `weapons.js`): `length` — длина пушки в
кадре в метрах, плюс смещение и доворот. Масштаб выводится из длины
(`viewScale` = length / `TARGET_LENGTH`), а не задаётся безымянным множителем:
с множителями порядок размеров в руках разъехался с мировым и снайперка
оказывалась короче дробовика. Сейчас в кадре 0.36 / 0.62 / 0.64 / 0.66 / 0.76 /
0.88 м (пистолет → ПП → рейл → автомат → дробовик → снайперка), что повторяет
порядок мировых `TARGET_LENGTH`. Чем длиннее пушка, тем дальше она отодвинута
от камеры, иначе в кадр попадает только казённая часть. Точки кистей (`rightHandPoint`/`leftHandPoint`)
считаются от позы оружия, а не задаются абсолютно: иначе при смене масштаба
рука повисает отдельно от грипа. Подбирать позы удобно на стенде —
`http://localhost:8123/tools/viewmodel_bench.html?w=sniper` для вида в руках и
`?mode=world` для сравнения всех шести пикапов рядом с ростовым силуэтом
(в релизный whitelist `tools/` не попадает). У стенда `<base href="/">`:
`weapons.js` грузит модели относительным путём, и из `/tools/` они бы 404-ились.

**Оптика снайперки**: труба с кронштейнами и линзой строится кодом
(`buildScope`) и живёт в holder рядом с моделью, а не внутри неё — внутри свой
масштаб нормализации, и прицел ушёл бы в микроскопический размер.
Прицеливание — правая кнопка мыши или кнопка `ОПТ` на мобильном: FOV плавно
уходит с 78 на `zoomFov` (30), чувствительность падает до 0.45, вьюмодель и
кисти прячутся, HUD показывает круглое поле с перекрестием. `zoomFov` есть
только у снайперки, и это закреплено тестом.

**Отдача разделена на две величины.** `recoil` — подброс прицела в радианах,
он реально уводит следующую пулю и гаснет экспоненциально (~0.4с). `viewKick` —
чисто визуальный откат модели, на попадание не влияет. У рейла и снайперки
подброс почти нулевой (0.012 и 0.016 — «выстрел в точку»), а удар отдаётся
увеличенным `viewKick`.

**Патроны.** У каждой пушки свой магазин (`mag`), запас патронов бесконечен —
ограничение только по времени (`reload`). Пустой магазин уходит в перезарядку
сам при нажатии огня, ручная — `R` на клавиатуре и кнопка `#btn-reload` на
мобильном. Смена пушки прерывает перезарядку, подобранная с земли всегда полная.
Рейл на зарядке перезарядить нельзя. Призраки-записи патронов не тратят: они
воспроизводят готовый timeline, поэтому перезарядка — механика только игрока.

Респаун пикапов — 10с. Пикапы smg/ar/sniper на arena01/02/04/05
(arena03 намеренно rail-only aim-карта). Редактор карт — 5 инструментов
точек оружия, редактор скинов — 6 панелей цветов.

**Кисть от первого лица** (`js/hands.js` `buildHand`, вынесена из player.js,
чтобы стенд и игра строили одну геометрию): маленький воксельный
кулак+манжета у грипа, цвета из `skin.body.arms/torso` + яркая полоска
цветом `skin.tracer` (чтобы не терялась на тёмных скинах). Не привязана к
геометрии пушки — размер фиксирован, не растёт вместе со снайперкой/рейлганом.
Покачивается синхронно с view-моделью пушки при ходьбе.

**Левая кисть** (`handL`, позы в `LEFT_HAND_POSE`): лежит на цевье двуручных
пушек, у пистолета появляется только на время перезарядки.

**Разворот кистей** (`HAND_REST`): без базового наклона предплечье шло строго
вдоль ствола и рука читалась бруском. Теперь обе кисти развёрнуты наружу и
вниз (~45°), у каждой добавлено предплечье, а масштаб уменьшен до 0.78/0.72 и
позиция отодвинута от камеры — на 0.32 м кулак занимал треть кадра. Яркая
полоска манжеты сужена: широкой пластиной она при наклоне смотрела в камеру
жёлтым квадратом.

Анимация перезарядки: связка поднимается в кадр и **одновременно отводится**
от камеры (иначе кулаки раздуваются), ствол кренится, левая кисть ныряет за
магазином и возвращается, в конце — короткий рывок стволом. Все три фазы
сняты скриншотами в headless-браузере: панель предпросмотра держит вкладку в
`hidden`, и rAF там не тикает.

## Интерфейс: шрифты, иконки, HUD

Шрифты self-host в `assets/fonts` (Russo One — заголовки, кнопки, HUD;
Exo 2 — текст и цифры), латиница и кириллица разделены `unicode-range`, всего
~65 КБ. Внешних запросов к Google Fonts нет — это требование модерации.

Иконки кнопок и HUD (`assets/icons`) генерируются через Visionary:
`node tools/gen_icons.mjs`, ключ из `VISIONARY_API_KEY` или локального `.env`.
Генератор рисует белый символ на чёрном фоне, ffmpeg вырезает фон в альфу и
приводит к 128×128 — в интерфейсе иконка занимает 26 px.

Силуэты пушек в HUD (`assets/hud`) не рисуются генератором, а рендерятся из тех
же GLTF-моделей, что игрок держит в руках: `tools/viewmodel_bench.html?mode=icon`
+ снимок с `omitBackground`. Рендерер стенда поэтому создаётся с `alpha: true` —
иначе силуэт уезжает в HUD вместе с чёрным прямоугольником.

Правый нижний угол собран как в CS:GO: силуэт текущей пушки, под ним название и
крупный счётчик патронов курсивом, слева от цифр — иконка магазина. У полоски
здоровья — сердце, перекрашенное CSS-фильтром под цвет урона.

## Звук выстрелов (js/audio.js)

Всё синтезируется, файлов нет. Выстрел собирается из слоёв, как настоящий:
`crack` — сухой щелчок пороха (шум через highpass, спад ~20–70 мс), `thump` —
низкий удар ствола с резким падением питча (он и даёт вес), `mech` — гильза и
затвор через несколько миллисекунд. Плюс общий процедурный реверб: impulse
response — экспоненциально затухающий шум 0.32 с, собирается в `buildReverb()`.
Без хвоста выстрелы звучали так, будто игрок стреляет в вате.

Замеры офлайн-рендера (пик / длительность): ПП 0.25 / 20 мс — самый короткий,
иначе 11 выстр./с сливаются в гул; пистолет 0.50 / 68 мс; автомат 0.45 / 71 мс;
рейлган 0.70 / 181 мс; снайперка 0.81 / 164 мс; дробовик 0.86 / 195 мс —
самый тяжёлый. Перезарядка тихая (0.10), чтобы не спорить с выстрелами.

## Музыка (js/music.js)

Шесть треков: тема меню и по одному на каждую арену. Генерируются через Suno
(`node tools/gen_music.mjs`, ключ только из `SUNO_API_KEY` или из
`suno_key.txt` рядом с репозиторием — в git он не попадает). Оригинал Suno
стерео ~3 МБ, поэтому ffmpeg режет до 72 с, сводит в моно и жмёт до 72 kbps:
563 КБ на трек, 3.4 МБ на все шесть.

Проигрывание — обычный `<audio>` с `loop`, отдельно от Web Audio: музыка не
держит AudioContext, грузится лениво (`preload="none"`) уже после `boot()` и не
задерживает старт. Автоплей до первого жеста блокируется браузером — это не
ошибка, модуль просто ждёт ближайшего `pointerdown`/`keydown` и повторяет.
Громкость 0.34, на паузе, рекламе и свёрнутой вкладке приглушается до 0.1 тем
же хуком, что и `Sound.suspend`. Тумблер «Музыка» — в настройках, состояние
едет в сейве (`settings.music`). У пользовательских и присланных карт своей
темы нет — для них играет `arena01`.

## Купол неба (assets/sky, tools/fetch_sky.mjs)

Панорамы — HDRI с [Poly Haven](https://polyhaven.com/hdris) под **CC0**, только
варианты `*_puresky`: в них одно небо. Обычные HDRI тащат фотографическую землю
(дорогу, дома), и у горизонта она спорит с вокселями.

`node tools/fetch_sky.mjs` качает 2k HDR, декодирует Radiance RGBE, считает
экспозицию по яркости самой панорамы и применяет ACES-тонмаппинг, на выходе
jpg 2048×1024 (~70 КБ на арену, 418 КБ на все шесть). Тонмаппинг делается
здесь, потому что ffmpeg в системе собран без zimg и его фильтр `tonemap`
недоступен. Экспозиция берёт минимум из двух оценок — по медиане неба и по
95-му перцентилю: одной медианы мало, равномерно светлое небо уходит в белое.
Ночь автоэкспозиция всё равно вытягивает до серого дня, поэтому у неё ручной
`bias` 0.16.

Почему не генерация: нейросети рисуют обычный кадр, а не развёртку сферы —
на куполе это давало вертикальный шов и «воронку» у зенита. Процедурный
рисовальщик шов убирал, но небо выходило плоским.

`loadSkybox` смотрит на соотношение сторон: 2:1 идёт на сферу как есть
(`equirectTexture`), достройка из широкого кадра осталась только для UGC-карт
со своей картинкой. Оттуда же берётся цвет тумана — полоса у горизонта, иначе
фиксированная тёплая дымка спорила бы с ночной панорамой.

## Экономика: госткоины

Двухступенчатая схема: **Яны → госткоины (только в одну сторону) → всё остальное**.
- Паки коинов (`skins/shop.json` → `packs`) — единственные товары в каталоге
  Яндекса; `Platform.buyCoinsPack` на Яндексе зовёт `ysdk.getPayments().purchase()`,
  локально — заглушка. Кнопки скрыты за `CONFIG.paymentsEnabled` (сейчас false).
- Награда за матч (`js/economy.js`): 8 базовых + 10×множитель сложности
  (`BUILTIN_MULTS` 1…1.6, `CUSTOM_BOT_MULTS` для ботов на своей карте) + бонусы
  (сухая 5:0 +4, призрак друга +12), первая победа дня ×2, rewarded-кнопка
  «Удвоить» на экране результатов. Анти-абьюз: бонус за одного и того же
  призрака друга не чаще 3 раз в день (хеш записи).
- Множители и правила матча (`WINS_TO_TAKE_MATCH`, тайминги раунда) живут
  только в `js/economy.js` — UI и симулятор берут их оттуда.
- Границу суток даёт часовой пояс устройства при доверенном `Platform.serverTime()`.
  Даты сравниваются лексикографически и двигаются только вперёд (`isNewDay`),
  поэтому перевод часов назад не открывает второй ×2 и не сбрасывает лимит.
- Магазин скинов: 5 встроенных (200/200/300/400/500) + слот «Свой скин»
  (`shop.customSkinPrice`, 300). Цену при покупке берёт `catalogSkinPrice` из
  каталога, а не из объекта UI. Стартовый баланс — 0 (`STARTING_COINS`).
- **Калибровка проверяется симуляцией**: `node tools/sim_economy.mjs` считает,
  за сколько минут игрок доходит до первого скина по четырём профилям
  (сейчас 27–64 мин без рекламы), а unit-тест держит нижнюю границу 20 минут.

## Шеринг и модерация

Вызов другу отдаёт ссылку только на ту площадку, где игра запущена. Внутри
Яндекса это страница игры в каталоге с `payload`: друг открывает её, и код
призрака подставляется сам (`Platform.getLaunchPayload`). Ссылки на свой
хостинг там нет — перенаправление трафика с площадки модерация не пропускает.

Проверка идёт по двум признакам: `Platform.isYandex` (SDK поднялся) **или**
`CONFIG.yandexBuild`. Второй нужен на случай, если SDK не загрузился: без него
игра свалилась бы в веб-ветку и предложила ссылку на GitHub Pages. В
репозитории флаг выключен (локально и на Pages ссылка нужна), а `npm run pack`
переписывает его в `true` прямо при упаковке — `lockToYandexBuild` в
`tools/pack_release.mjs`. Забыть про него нельзя: если строка в конфиге не
найдена, сборка падает.

Когда ссылки нет (пустой `yandexAppId` или код длиннее `yandexPayloadLimit`),
шеринг копирует сам код, а друг вставляет его в «Код призрака».

## Задел: покупки за Яны (в этом релизе выключены)

Схема уже реализована целиком и намеренно обесточена одним флагом
`CONFIG.paymentsEnabled = false`: пока он false, блок паков в магазине даже не
строится, а `Platform.buyCoinsPack` возвращает кошелёк без изменений с ошибкой
`payments_unavailable`. Чтобы включить в следующем обновлении, нужно:

1. Завести товары `pack_s` / `pack_m` / `pack_l` в консоли Яндекс.Игр.
2. Сверить начисления с `CONFIG.coinPackGrants` — код берёт количество монет
   только оттуда, значение из каталога не считается доверенным.
3. Поставить `paymentsEnabled = true`.

Всё остальное готово и покрыто тестами: `getPayments()` с очередью запросов,
`consumePurchase` строго после успешного сохранения кошелька, ledger по
`purchaseToken` (повторная выдача монет невозможна), восстановление незакрытых
покупок при старте (`recoverPurchases`). Скины продаются только за госткоины —
второй ступенью, и эта развязка сохраняется: Яны → госткоины → всё остальное.

## Интерфейс: экраны

Меню: логотип, ротация подсказок (`tip1…tip8` в i18n, своя на каждый заход —
раньше там висел английский слоган) и шесть кнопок одинаковой ширины с
иконками. `Как играть` (`buildHowTo`) — шесть карточек: цель, кто такой
призрак, управление, оружие, награда, вызов другу.

Магазин: карточка скина показывает превью — если сгенерирована картинка
(`assets/skins/<id>.jpg`, `tools/gen_skin_cards.mjs`), она подставляется фоном;
если нет, рисуется силуэт призрака в цветах самого скина поверх градиента из
его палитры. Так магазин выглядит одинаково цельно и с артом, и без него.

## Яндекс Игры

`js/platform.js` автоопределяет окружение: пробует загрузить `/sdk.js`
(существует только на CDN Яндекса) → настоящий SDK; иначе localStorage-заглушки.
Локальная разработка и GitHub Pages работают без изменений. Реализовано:
`YaGames.init`, rewarded/interstitial реклама (глушит звук на время показа),
облачные сейвы (`player.setData/getData` + localStorage-фолбэк), лидерборды,
покупки Payments с consume, `LoadingAPI.ready()` в конце boot (после прелоадера).

**Перед заливкой в консоль**:
1. Вписать ID игры в `CONFIG.yandexAppId` (js/config.js) — без него шеринг
   внутри Яндекса работает кодом, а не ссылкой на каталог
2. Завести 3 товара `pack_s`/`pack_m`/`pack_l` (цены в Янах — см. `skins/shop.json`)
   и лидерборд `wins`, затем `paymentsEnabled: true`
3. На чистом worktree выполнить `npm test`, затем
   `powershell -File tools/pack_yandex.ps1` и сверить `.sha256` перед загрузкой

**Шеринг по окружениям**: на Яндексе —
`https://yandex.ru/games/app/<yandexAppId>?payload=<код>` (только внутри
Яндекса, внешних доменов в UI нет — прошёл аудит модерации); вне Яндекса —
`<CONFIG.shareBaseUrl>?ghost=<код>`.

## Деплой

GitHub Pages через Actions (`.github/workflows/pages.yml`) — на каждый push в
main запускает тот же `npm test`, что и CI, затем публикует staging-каталог из
`tools/stage_runtime.mjs`, а не весь checkout. ZIP и Pages используют общий
whitelist `tools/lib/runtime.mjs`.

## Известные проблемы

- Pointer lock недоступен в sandbox-iframe (встроенные превью) — работает
  фолбэк: камера от движения мыши без захвата; в обычной вкладке всё штатно.
- Призрак не сталкивается с геометрией (движется по записи) — записи с другой
  карты могли бы проходить сквозь стены, но шеринг несёт `mapData`, поэтому
  штатный путь безопасен.
- В фоновой вкладке rAF троттлится — отсчёт/матч замирают (не баг для игрока).
- Автоогонь на мобиле проверяет LOS от призрака, конус 6° — может огорчать на
  сверхдальних дистанциях (намеренно, чтобы не палил через пол-карты).
- У sky-dome остаётся один долготный стык; 96-пиксельный edge-crossfade в
  подготовленных панорамах делает его менее заметным, но не устраняет сам шов.
